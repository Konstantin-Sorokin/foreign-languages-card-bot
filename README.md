# Foreign Languages Cards Bot

Telegram-бот для изучения английского языка. Позволяет добавлять собственные карточки со словами и примерами, подключать готовые наборы (паки) и тренировать неправильные глаголы. Обучение строится на повторении карточек с учётом прогресса пользователя, а напоминания о повторении приходят через RabbitMQ.

---

## Возможности

- Повторение карточек с учётом прогресса пользователя;
- Создание собственных карточек (слово, перевод, пример, перевод примера);
- Добавление готовых паков в обучение (дерево категорий и наборов с хлебными крошками);
- Изучение неправильных глаголов по группам спряжения, а также в случайном режиме;
- Напоминания о карточках для повторения через RabbitMQ-уведомления;
- Автоматическая регистрация пользователя при первом обращении;
- Ограничение частоты запросов (троттлинг) на основе Redis.

## Архитектура

Бот не хранит данные самостоятельно: вся бизнес-логика и хранение находятся во внешнем API. Взаимодействие с ним выполняется через HTTP-клиенты (aiohttp).

```
Telegram
    ↓ (polling)
aiogram Bot
    ↓
Middleware (троттлинг, регистрация пользователя)
    ↓
Handlers
    ↓
Services
    ↓
API-клиенты (aiohttp)
    ↓
Внешний API
```

Отдельно работает потребитель RabbitMQ: внешняя система публикует уведомления в очередь `notifications`, бот слушает её и отправляет сообщения пользователям в Telegram.

```
Внешняя система → RabbitMQ (очередь notifications)
                        ↓
              NotificationConsumer
                        ↓
              NotificationHandler
                        ↓
                    Telegram Bot
```

## Запуск проекта

1. Клонировать репозиторий:

```bash
git clone git@github-home:Konstantin-Sorokin/foreign-languages-card-bot.git
cd foreign-languages-card-bot
```

2. Создать файл `.env` из шаблона и заполнить его:

```bash
cp .env.template .env
```

3. Создать внешнюю Docker-сеть (используется в `docker-compose.yml`):

```bash
docker network create flc_backend
```

4. Запустить бота:

```bash
docker compose up --build
```

> Redis и RabbitMQ предполагаются развёрнутыми отдельно и доступными по адресам из `.env`. В `docker-compose.yml` определён только сервис `bot`.

Миграции не требуются: проект не использует собственную базу данных.

## Переменные окружения

Основные переменные из `.env.template`:

- `TOKEN` — токен Telegram-бота;
- `PROXY_URL` — адрес прокси для доступа к Telegram API (необязательно);
- `API_URL` — адрес внешнего API;
- `REDIS__HOST` — хост Redis;
- `REDIS__PORT` — порт Redis;
- `REDIS__DB` — номер базы Redis.

Также приложением читается переменная `RABBIT__URL` — строка подключения к RabbitMQ (используется для получения уведомлений).

## API

Бот обращается к внешнему API по следующим эндпоинтам:

- `POST /users/` — получение или создание пользователя;
- `POST /cards/` — сохранение новой карточки;
- `GET /learning/{user_id}/due` — карточки, подлежащие повторению;
- `PATCH /learning/cards/{card_id}` — обновление прогресса по карточке;
- `GET /learning/irregular-verbs?group=...` — неправильные глаголы по группе;
- `GET /learning/irregular-verbs/random` — случайный набор неправильных глаголов;
- `GET /packs/` — список всех паков;
- `GET /packs/{pack_id}?user_id=...` — содержимое пака с учётом подписки пользователя;
- `GET /packs/{pack_id}/cards` — карточки пака;
- `POST /packs/{pack_id}/add` — подписка пользователя на пак.

## Фоновая обработка (RabbitMQ)

Для доставки напоминаний используется RabbitMQ. При старте бот создаёт устойчивую очередь `notifications` и начинает её слушать. Каждое сообщение валидируется Pydantic-схемой и обрабатывается `NotificationHandler`.

Поддерживаемые события:

- `learning_reminder` — отправка пользователю напоминания «📚 У вас есть карточки для повторения».

## Интерфейс

Интерфейс реализован через Telegram:

- **Главное меню** (`/start`) — выбор между обучением и добавлением карточек;
- **Обучение** — повторение собственных карточек с учётом прогресса и изучение неправильных глаголов (по группам или в случайном режиме);
- **Добавление** — создание собственной карточки (пошаговый ввод через FSM) или подключение готового пака;
- **Справка** (`/help`) — описание возможностей бота.

## Особенности реализации

- **Очередь карточек в Redis.** Карточки для повторения загружаются из API в Redis-список. При правильном ответе карточка извлекается из очереди (`LPOP`), при неправильном — возвращается в конец очереди для повторного показа.
- **Кэширование пользователей.** Внутренний идентификатор пользователя кэшируется в Redis (`user:{telegram_id}:id`, TTL 24 часа), что сокращает число запросов к API.
- **In-memory хранилище.** Паки и неправильные глаголы загружаются из API при старте и хранятся в памяти: дерево паков позволяет строить хлебные крошки и навигацию по категориям/наборам.
- **FSM на Redis.** Состояния диалогов (добавление карточки) хранятся в `RedisStorage`.
- **Троттлинг.** Ограничение частоты сообщений и колбэков реализовано через атомарную операцию Redis `SET NX PX`.
- **Нормализация текста.** Все текстовые поля карточек нормализуются (схлопывание повторяющихся пробелов).
- **Автоматическая регистрация.** Middleware `UserMiddleware` создаёт пользователя при первом обращении и сохраняет его идентификатор в кэше.
